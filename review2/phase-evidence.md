## 2 — Email and MFA

The exact locked RelayKt v1.0.9 and Keep v1.0.15 jars were inspected with `javap`; dumps are in `evidence/framework/`. Nearby library source trees have different versions and were not treated as release evidence.

| Question | Verified behavior / limit |
|---|---|
| Implicit SSL and STARTTLS | RelayKt supports both. SMTP defaults to port 587, STARTTLS enabled/required, implicit SSL off. SmtpServiceType does not reject both TLS modes or contradictory port choices at save time; service testing is required. |
| Hostname verification | `mail.smtp.ssl.checkserveridentity=false` is compensated by the custom SmtpSocketFactory setting endpoint identification to HTTPS. Do not report hostname verification disabled from that property alone. |
| CA and pins | A supplied CA builds a custom trust store instead of simply adding to platform roots. Pin checks apply to the SMTP socket trust manager and compare public-key material. A renewed certificate using the same key is not necessarily a pin failure; test HH's actual rotation procedure. |
| MFA outage | `PasswordLoginController` → `MfaService` → `SystemManager` sends synchronously inside the request transaction. Failure gives a server error, does not issue a session, and can roll back the failure alert. No live HH relay was contacted. |
| Recovery | Harness README documents `MFA_ENABLED=false`; recreate the server with the existing host credentials, repair/test mail, then re-enable MFA and test a fresh sign-in. Keep host recovery access and a named custodian. An existing browser session is not a durable recovery plan. |
| Budgets | MFA defaults: six digits, five-minute lifetime, five wrong codes. Resend resets attempts and extends expiry on the same token. HTTP limits: verify 10/minute/IP, resend 3/minute/IP, login 10/minute/IP (`SessionRoutes.kt:29`). Password account lockout is separate. |
| Zero/multiple system services | Zero throws “No active email service is enabled for system emails.” Multiple eligible services are selected randomly; this is not failover. Require exactly one tested active system sender on the HH appliance. |
| Workflow contents | Development seed uses the fixed subject “Unexpected pathology result”, reason/unexpected summary/report summary in the body, no attachments, and `system@aideway.local` as recipient. | Queue | Durable database queue with encrypted payload, 20-second dispatch interval, default five attempts and exponential delays from 120 seconds (approximately 2, 4, 8, 16 minutes between attempts; dispatch cadence adds latency). Stale PENDING is requeued, but stale SENDING becomes TIMED_OUT, not an automatic resend. Retries require a recoverable exception; SendFailedException is always marked nonrecoverable without separating recipient 4xx deferral. Terminal failed/timed-out is not delivered; workflow success means enqueue, not mailbox receipt. |
| Queue governance | Initial node authorization exists, but delayed dispatch reconstructs the endpoint without rechecking activity/tier/TLS policy. EmailAuditQueue/EmailAuditJob are not the path used by EmailClient.queue. No application terminal-delivery alert is wired. |

No configurable EHLO override is set, so local/container identity may be used. HH must test accepted sender, relay source IP, EHLO rules, MIME/line handling, and quarantine; no unsupported Exchange/Graph/OAuth integration is assumed. |
| Timeouts | Exact jar defaults are 10 seconds each for connect/read/write, not an overall ten-second request deadline. A slow relay holds the login request and its transaction during synchronous send. |

| Logging | Application paths generally log safe service/queue IDs. RelayKt sanitizes SendFailedException addresses, but general MessagingException causes can retain provider text. Alert stack traces and job logs must be tested with synthetic relay diagnostics; no claim of universal redaction is justified. |

Shared mailbox sign-in provides shared attribution, regardless of password and emailed OTP. Recommend named HH accounts and appropriate Administrator/Security Officer separation. Domain DNS supplied by the instructions does not establish internal relay details or external forwarding safety; those remain HH questions.

## 3 — Report share and file trigger

- The guide's `cifs-utils` / `nfs-common` install steps need offline packages if DGX OS lacks them. This sandbox cannot establish the factory image's package set. SMB credentials are expected root-owned mode 0600. `drop.cred` and site fstab/export settings are not covered by the ordinary backup or the narrow `70-file-perms` check.
- CIFS UID mapping to 1001 can permit server writes/deletes only if server-side ACLs also allow them. Guide `gid=1001` is not necessarily the generated operator GID. NFS `root_squash` alone does not remap UID 1001; HH must align export permissions or deliberately map an all-squashed identity. `sec=sys` does not establish transport encryption. Verify HH's accepted protocol/security mode.
- Bind propagation defaults to rprivate, as confirmed by [Docker's bind-mount documentation](https://docs.docker.com/engine/storage/bind-mounts/). The guide's server recreation after mounting is necessary. `nofail`/automount in fstab does not erase the application's explicit RequiresMountsFor dependency; test outage at boot separately from an outage after startup.
- File handling is polling, not inotify: validation and sweep jobs have separate schedules. A stable fingerprint across sweeps or sufficiently old modification time makes a file eligible. Atomic rename from a nonmatching temporary name is required; in-place writes with pauses can look complete.
- Identity is based on filesystem/file identity, size and timestamps, not content hash. Identical redelivery under another name can run again. Optional name dedupe can suppress a corrected report with the same name, and suppressed files are still deleted when deletion is enabled. The seed does not explicitly enable that option; classify this as conditional until the HH artifact is inspected.
- For CREATED/UPDATED modes, a fresh ledger baselines existing files. FILE_ADDED deliberately handles existing files and requires deletion. Mount timing and existing ledger state affect this: do not promise that every first sweep always ignores backlog. Reconcile all go-live files before enabling the workflow.
- Deletion follows durable launch, not successful analysis. Failure to launch remains retryable; failure later in execution does not reset ingestion state. ACL-denied deletes are retained as pending deletes and retried without a new launch. Encrypted execution input usually remains recoverable according to retention; source deletion is not proof all copies were lost.
- Regex controls eligibility, so a hidden or lock file ending `.pdf` can match. Nonmatching files are ignored; zero-byte files can pass conversion as empty; encrypted/invalid PDFs fail parsing; image-only PDFs require working OCR; excessive bytes are skipped as oversized. Traversal and symlink protections exist in WatchedDirectoryScanner/ProtectedFileSystemRoots. Subdirectory behavior is configuration-driven and must match the producer contract.
- PDF page/image limits exist, but no dedicated OCR wall-time/concurrency budget protects all conversion work. `PYTHON_BRIDGE_TIMEOUT_SECONDS` is not a Tesseract timeout. Validate scanned, malformed, large and mixed-page reports on the release image.
- Read/missing-directory errors create runtime states and alerts and later sweeps can recover. A mounted-but-empty placeholder or a replacement mount invisible to the container is different and can look healthy. An external intake counter is needed.
- Filenames appear in watched-file metadata/UI and some execution context; the seed email subject is fixed. Never permit patient identifiers in producer filenames. Read-only container roots/capability drops do not by themselves prevent writes to an explicitly writable bind; actual UID/ACL/LSM controls still need a delete probe.

## 4 — Workflow and clinical outcomes

The dev graph is trigger → conversion → ICD enrichment → analysis, then parallel dataset and unexpected-result filter branches. The true branch queues mail and attempts a personal notification; its CATEGORY_2 mapping is not a valid NotificationUrgency enum value and decoding fails (DevWorkflowSeeder.kt:974; NotificationUrgency.kt:16). It does not implement the exact customer-guide promise. `backend:dev` is separate from the production distribution. Offline definition import validates versioned definitions and resolves local bindings but does not provision all site prerequisites or publish them.

The workflow pins prompt/dataset revisions and a classification configuration revision at launch. Runtime tier checks use current policy; classifier configuration snapshots do not prove identical NER model weights because model digests remain placeholders. With no tiers, access checks allow all; with tiers, unknown/incomplete classification is conservative unless the accessor has the highest clearance. The site must establish tiers and declarations before PHI, including full report text and summaries; successful NER is not proof that text contains no PHI.

The exact installed model/quantization/revision and active prompt are not known. Request schema is supplied to the provider, but the application accepts any JSON object. The retained compiled-code probes show `{}` succeeds with STOP and MAX_TOKENS and that image-only/zero-byte input produces empty text with default OCR settings. These are deterministic application gaps, not a measured clinical false-negative rate. A confidence field does not create a review policy: the seed filter tests only `unexpected_result`.

Workflow concurrency defaults to one; runtime/timeout/retry limits are optional. vLLM restart causes a call failure unless service-health waiting/retry policy covers the specific point of interruption. No complete production graph was run because the HH bundle, GPU/model and services were unavailable. Unit/integration and synthetic parser/PDF checks are evidence for their narrower contracts only.

The execution job foreign key now uses SET_NULL, preserving history when jobs are cleaned up. Other prior restart/cancel/idempotency issues are recorded individually in the prior register. An execution may be replayed at least once; there is no universal exactly-once email guarantee. The default graph's CONTINUE policies and parallel record branch require outcome reconciliation.

Dataset fields have per-field encryption and blind-index controls; encrypted equality search does not imply plaintext sorting/range/substring support. Security Officer access and HH reader access must be tested against the published dataset and current tier rules. Workflow message purge does not purge dataset records, mailboxes, audit metadata or backups. Record the separate retention periods and prove them with synthetic data.

- Cloud OpenAI/Anthropic/Google, HTTP and FHIR types are registered alongside local vLLM and SMTP. ## 7 — Model and prompt evaluation
