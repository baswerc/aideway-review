# Evidence index

All evidence was collected locally on 2026-10-15. No HH connection or patient data was used. The main [baseline](../00-baseline.md) records exact results, failures, skips and limits. Logs are test output, not production telemetry.

- `gradle-build.log`, `backend-initial-results.json`: initial fresh aggregate build and its retained 2,806-case results. Later focused runs replace Gradle's XML output, so the initial summary is preserved separately.
- `focused-and-frontend.log`: 40 backend permission-sensitive cases with DAC bypass removed and 661 frontend tests. `frontend-build-fresh.log`: fresh lint/type-check/build.
- `harness-tests.log`, `harness-corrected-path.log`, `harness-permission-tests.log`: main and focused harness runs. `python-scripts.log`, `nginx-container-tests.log`, `python-ner-tests.log`, `vllm-build-tests.log`: additional checks.
- `extended-checks.log`, `test-inventory.json`: PHI corpus, skipped NER integration, generated API verification and mockup tests. The inventory describes the final focused XMLs, not a replacement full backend run.
- `release-schema.log`, `dependency-verification.log`: still-failing release checks. Do not reinterpret them as passing because ordinary build settings bypass verification.
- `ClinicalProbe.java`, `clinical-probes.log`: invokes compiled production PDF conversion and analysis-response handling with marked synthetic material. It does not call an LLM, open a database or contact HH. From workspace root after building the distribution: `javac -cp 'projects/aideway/backend/build/install/aideway/lib/*' -d review2/evidence review2/evidence/ClinicalProbe.java`, then `java -Djava.awt.headless=true -cp 'projects/aideway/backend/build/install/aideway/lib/*:review2/evidence' ClinicalProbe`. Use the reviewed default OCR environment; an explicitly configured OCR installation changes that branch. The generated class is not retained.
- `harness-probes.py`, `harness-probes.json`: temporary isolated fixtures for audit crash masking, CLI parsing, container-flag checking, docs dependency and inert shell-value interpretation. No host mount/backup/service mutation was performed.
- `framework/`: javap output for the exact locked jars and class inventories. `jar-manifest.json` records the installed jar hashes; nearby framework source of other versions was not substituted for these dependencies.
- `dependency-review.md`, `npm-audit.json`, `runtime-dependencies.log`, `maven-*`, `advisories/`: complete lockfile scan and reachability analysis. All 82 returned GHSA details were fetched. `fetch-advisories.py` and `build-dependency-report.py` reproduce retrieval/report assembly. The older sequential `scan-maven.py` attempt timed out and is not the reported result; complete batch responses are authoritative.
- `current-source-citations.json`: 294 final prior-item entries with current source snippets and file hashes. `prior-source-crosscheck.json` is the intermediate register imported from review 1; some old engine line references were stale and are superseded by the current file. `prior-register.py` documents that import, while `build-prior-report.py` applies the source rechecks/corrections and creates the final table. Counts are source items, not unique defects.
- `docs-link-check.json`: unresolved Markdown links. `docs-inventory.json`: source hashes for guide files, not a claim every image was inspected. `contrast.json`: calculated source-token contrast, not rendered browser measurements.

The review files contain no private-key, password or runtime `.env` dump. Hashes in the install kit identify public trust-key files only and do not authorize replacing a site's trust roots. Source/analysis scripts do not create a deployment approval.
